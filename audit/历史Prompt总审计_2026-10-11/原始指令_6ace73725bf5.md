# 《宫灯未眠》结局系统全面检查与回访功能修复 Prompt

## 一、核心任务

请检查当前《宫灯未眠》项目中所有涉及终章、结局、走马灯、词谱（或项目中对应的诗词内容）、全剧终画面及相关导航的代码。

**核心问题：玩家观看完整结局之后，可能无法正常返回，或者无法再次进入结局页面回看。**

请直接检查、修复并测试，确保所有结局内容可以正常进入、观看、返回和再次回访。

本次重点是修复现有功能与整理结局体验，不重写剧情、不新增复杂系统。

## 二、首先检查完整的结局流程

追踪以下实际调用关系：

正式终章 → 最终结局正文 → 结局走马灯 → 诗词/题辞内容 → 全剧终 → 后续操作。

具体顺序必须以现有项目为准，不要擅自改变已经确定的结局演出。

逐一确认：

1. 走马灯正常播放完毕后会发生什么？
2. 是否存在无法退出的黑屏或静态结束画面？
3. 最后一段动画是否阻止其他导航事件触发？
4. 全剧终页面是否有明确的返回入口？
5. 玩家能否重新观看完整走马灯？
6. 进入诗词或词谱页面后，能否正常返回？
7. 从结局返回后，再次进入是否会出现异常？
8. 是否因为结局标记、章节索引或状态锁定，导致玩家无法回访？

不得仅检查按钮是否存在，必须验证按钮是否真的可用。

## 三、完善全剧终界面

结局播放完毕后，不应直接停留在无法操作的终止状态。

请根据现有 UI 风格，为最终画面安排清晰、精致、克制的导航。

建议包含以下操作：

**重温走马灯**

重新播放已经解锁的结局走马灯。

从第一幕开始正常播放，直到最后的“宫灯未眠”。

重复播放不得再次触发不应重复执行的剧情奖励、角色状态修改或结局结算。

**回看结局**

返回当前已达成结局的正文起点，允许玩家重新阅读。

回看过程必须保持人物称号、结局分支和相关文本一致。

**返回目录**

返回现有章节目录、故事菜单或结局回顾入口。

优先复用项目已有导航，不要创建功能重复的新菜单。

**返回首页**

返回《宫灯未眠》的主封面。

返回首页不应自动删除或覆盖已有存档。

如已有其他功能完善的导航入口，可整合而不是重复添加按钮。

## 四、结局回访机制

检查现有章节目录、存档、结局记录和相关菜单。

玩家首次完成结局之后，应能够在后续重新进入已经解锁的内容。

重点包括：

- 已达成的结局正文
- 对应的走马灯
- 结局诗词、题辞或词谱内容
- 全剧终画面

优先使用现有解锁、存档和目录机制。

如果项目已有结局回顾入口，请直接修复并完善它。

如果没有，请以最小必要改动增加可回访入口，不要额外制作大型结局图鉴系统。

未达成的其他结局必须继续遵守原有解锁规则。

## 五、检查返回时的状态恢复

这是最重要的技术检查。

请重点验证：

1. 返回按钮是否存在正确的事件处理。
2. 是否有透明遮罩或动画层阻挡点击。
3. 走马灯播放状态是否在退出时正确清理。
4. 动画、音频和异步回调是否会在返回后继续运行。
5. 章节索引是否在回访时正确恢复。
6. 结局完成标记是否错误阻止重新进入。
7. 结局回顾是否意外修改正式存档。
8. 再次进入时是否出现重复字幕、音频叠加或画面闪烁。
9. 手机端的返回按钮是否可见、可点击。
10. 返回上级页面后，原本的导航是否仍然正常。

特别注意区分：

**正常推进剧情**与**回顾已经完成的剧情**。

玩家重看结局时，不应意外覆盖正式剧情进度。

## 六、结局走马灯体验优化

保留此前确定的走马灯诗句与关键剧情回顾，不擅自修改内容。

重点整理以下体验：

- 每幕切换自然。
- 诗句显示完整。
- 字幕不会被按钮遮挡。
- 走马灯播放结束后正常显示结束菜单。
- 可以主动跳过动画，直接进入结束菜单。
- 观看过程中若需要退出，应有明确且易操作的退出方式。
- 再次播放时，动画、声音和字幕从正确状态开始。
- 返回后不会出现残留的黑色遮罩或无法操作的问题。

不要在画面中央堆积大型现代按钮。

推荐使用与《宫灯未眠》一致的细金边、暗色题签和克制的古风交互样式。

让最终导航像故事的收卷，而不是普通网页操作面板。

## 七、特殊情况下的导航测试

请实际测试以下完整路径：

| 测试路径 | 预期结果 |
|---|---|
| 终章 → 走马灯 → 全剧终 | 正常结束并显示操作入口 |
| 全剧终 → 重温走马灯 | 能够重新完整播放 |
| 全剧终 → 回看结局 | 进入正确的结局正文 |
| 全剧终 → 返回目录 | 正常返回 |
| 全剧终 → 返回首页 | 首页正常、存档保留 |
| 目录 → 已解锁结局 | 可以重新进入 |
| 词谱/题辞 → 返回 | 返回正确的上级页面 |
| 走马灯播放中 → 退出 | 无残留动画或遮罩 |
| 走马灯 → 退出 → 再次进入 | 不黑屏、不重复音频 |
| 读档 → 重新完成结局 | 完成后导航正常 |
| 手机端完成结局 | 导航完整、按钮可操作 |

如游戏存在多个结局分支，必须至少测试各分支的结束和返回路径，避免只修好其中一条路线。

## 八、必须遵守的修改边界

1. 不修改现有结局的文学内容。
2. 不修改六句题辞或走马灯诗句。
3. 不改变杨叙、张元照及其他人物的既定结局。
4. 不破坏章节目录、大事录、存档和读档。
5. 不擅自更改已有结局解锁条件。
6. 不新增不必要的独立页面。
7. 不以刷新网页代替正常返回。
8. 不把所有结局统一导向错误的公共页面。
9. 不使用会造成存档污染的临时跳转方案。
10. 保持电脑端与手机端交互一致。

## 九、交付与验收

请直接检查和修复项目代码。

完成后提供：

**1. 原有问题**

明确指出无法返回或无法回访的具体原因及位置。

**2. 修改内容**

列出修改的文件、函数、导航入口和结局状态处理。

**3. 最终结局流程**

用简洁的流程说明玩家如何完成、退出、重看和返回。

**4. 实际测试**

报告上述每条测试路径的结果，并注明无法验证的部分。

保证玩家完成《宫灯未眠》之后，仍然可以回到游戏、查看已经解锁的结局、重温走马灯，而不是永远停留在最后一幕。

## 十、最终设计目标

《宫灯未眠》的故事可以结束，但玩家与故事的联系不应该被强行切断。

当最后一句“宫灯未眠”淡去，玩家可以安静地停留，也可以重温故人旧事。

最终页面应当有一种合卷之后仍可重新翻开的感觉。

**请优先解决所有返回、回访、循环播放与状态恢复问题，确认功能可靠后，再做必要的视觉整理。**
